1. 靈感發想島

L1 靈感層-Ask Gemini

示意｜學習目標：能將年級、主題與限制寫成具體提問，規劃教學靈感。

把瀏覽中的資訊變成靈感

原稿將 Ask Gemini 定位為 Chrome 內建的 AI 側邊欄助理，適合摘要、多資料統整與跨應用協作。從目前閱讀的網頁出發，先說明教學對象與想解決的問題。

原稿操作路徑

點選右上角圖示，詢問單頁重點；需要統整時加入分頁（原稿記載最多 10 個）；輸入 / 呼叫常態指令；從「更多」載入近期對話。原稿也示範依網頁內容撰寫並寄送 Gmail。

教學應用

以小六媒體識讀為例，將 40 分鐘課程、3 個破冰活動、不需複雜道具與學生熟悉的平台等條件一起交代，讓發想更具體。

根據【當前這個網頁】的內容，身為一位國小六年級的老師，我正在規劃一堂 40 分鐘的「媒體識讀與假新聞辨識」課程。請給我 3 個生動有趣的破冰活動提案。

  要求：
  1. 無需複雜的實體道具。
  2. 能引起小六學生的共鳴。
  3. 情境需結合時下流行的網路平台（如 YouTube、TikTok、IG）。

問問Gemini簡報 (Canva)

中央社新聞連結 (範例材料)

AI 提示詞工具庫 (Google Sites)

自編練習題｜學習單

  2. 依教材的提示詞範例，寫出三項讓 AI 發想更具體的限制。
  3. 規劃如何運用單頁摘要或分頁統整，協助你的備課。

2. 專屬助教島

L2 模組層-Gems

示意｜學習目標：能為重複教學工作設計角色、輸入條件與輸出格式。

打造固定風格的助教

Gems 封裝特定 Prompt 與知識庫，適合固定格式、重複性產出，例如依教學風格生成學習單。

原稿操作路徑

在左側選單點選「建立 Gem」，貼入系統指令。往後輸入學科、年級、單元等關鍵字，讓專屬助教依既定格式處理。

把期待寫進指令

教材範例包含素養導向表現任務、情境與探究問題，以及「優、良、可、待加強」四級評量規準。資訊不足時應先詢問。

你是一位熟悉台灣 108 課綱的專業課程設計專家。

  當我輸入【學科、年級、單元主題】時，請自動執行：
  1. 產出一份「素養導向」的表現任務學習單（含情境、探究問題、任務）。
  2. 附帶一份包含「優、良、可、待加強」的評量規準（Rubrics）表。

  要求：保持專業、鼓勵，層次分明，使用繁體中文。若資訊不足請主動詢問。

點擊體驗：Gem 範例連結

自編練習題｜學習單

  1. 選一項反覆執行的教學工作，描述專屬助教的角色。
  2. 寫出這個 Gem 每次需要接收的三個輸入條件。
  3. 設計輸出格式，並說明資料不足時助教應如何處理。

自編練習題｜測驗與解析

Gems 最適合教材中的哪種工作？
  • 固定格式的重複性產出
  • 更換電腦硬體
  • 維修校園網路
  • 紙張裁切

答案：固定格式的重複性產出。原稿以學習單產生器等固定風格與格式的工作說明。

建立專屬助教時，原稿要求貼入什麼？
  • 系統指令
  • 印表機驅動程式
  • 瀏覽器歷史紀錄
  • 學生密碼

答案：系統指令。系統指令封裝角色、產出規格與要求。

教材範例的評量規準包含幾個等級？
  • 四級
  • 兩級
  • 六級
  • 八級

答案：四級。分別為優、良、可、待加強。

範例系統指令遇到資訊不足時應如何處理？
  • 主動詢問
  • 自行虛構
  • 忽略所有要求
  • 停止顯示內容

答案：主動詢問。原稿明確要求資訊不足時主動詢問。

3. 技能工作坊

L3 擴充層-Skill

示意｜學習目標：能將教學需求拆成參數、步驟與檢核條件。

將方法拆成可執行步驟

原稿將 Skill 定位為具備邏輯判斷與程序步驟的結構化外掛，適合教案展開、雙向細目表與評量矩陣等工作。透過結構化步驟與檢核提高一致性，產出仍須確認。

原稿調用方式

輸入 @指令 或 /指令等喚醒詞，再用 Key-Value 方式給參數。範例參數包含單元名稱、年級、節數、核心素養、認知階層與輸出格式。

多 Skill 串聯

原稿示範先以教案 Skill 生成課程，再交給評量規準 Skill，最後用互動網站生成 Skill 製作教學網站。每一階段應檢視輸出是否符合下一階段需求。

@tw-spark-edu-lesson-plan
  請為我生成一份完整教案，參數設定如下：
  - 單元名稱：假新聞偵探團（媒體識讀）
  - 適用年級：國小六年級
  - 節數：1 節課（40 分鐘）
  - 核心素養：J-B2 科技資訊與媒體素養
  - 認知階層：強調布魯姆「分析」與「評鑑」層次
  - 輸出格式：包含「教學目標、雙向細目表、三階段教學活動（引起動機、發展活動、綜合活動）、時間分配」之結構化表格。

AI Skill 智慧開發工作台

自編練習題｜學習單

  1. 為一個單元列出年級、節數、認知階層及輸出格式。
  2. 將教材生產拆成教案、評量與網站三個步驟，說明彼此如何交接。
  3. 寫出你會用來檢核 Skill 產出的一項標準。

自編練習題｜測驗與解析

Skill 的輸入條件在教材中採哪種方式？
  • 參數化 Key-Value
  • 只傳空白訊息
  • 隨機輸入符號
  • 完全不給條件

答案：參數化 Key-Value。教材用年級、節數等明確參數示範。

哪項是教材列出的 Skill 參數？
  • 認知階層
  • 學生帳號密碼
  • 主機序號
  • 瀏覽器下載紀錄

答案：認知階層。原稿以分析、評鑑等認知階層設定教案方向。

多 Skill 範例的合理順序是？
  • 教案 → 評量規準 → 互動網站
  • 網站 → 刪除教材 → 不評量
  • 歸檔 → 關機 → 收款
  • 點名 → 維修 → 裁紙

答案：教案 → 評量規準 → 互動網站。原稿示範先建立課程，再依課程設計評量及網站。

對結構化 Skill 產出應採取哪種態度？
  • 透過步驟提高一致性，產出仍須確認
  • 保證永遠零錯誤
  • 無需閱讀就公開
  • 所有參數皆可省略

答案：透過步驟提高一致性，產出仍須確認。依使用者核准修訂，結構化不能取代人工確認。

4. Gems vs Skill

Gems 與 Skill 的決定性差異

示意｜學習目標：能依工作需求比較 Gems 與 Skill，說明選擇理由。

比較工作方式

教材以 Persona 與 Workflow 比較兩者：Gems 透過系統指令與知識庫設定角色及語氣；Skill 透過結構化參數、程序與檢核封裝專業方法。

比較優點與限制

Gems 設定直覺、富有彈性與創意，但複雜格式可能遺漏規則。Skill 需要清楚的參數與結構化思考；透過結構化步驟與檢核提高一致性，產出仍須確認。

教師選擇指南

潤飾聯絡簿、情境故事等工作，可考慮 Gems；雙向細目表、Rubrics 或跨模組教材流程，可考慮 Skill。原稿也提出在 Gem 中喚醒 Skill 的協作方式。

自編練習題｜學習單

  1. 提出一項適合 Gems 的工作，並說明選擇理由。
  2. 提出一項適合 Skill 的工作，說明需提供哪些參數。
  3. 比較兩者的限制，寫出產出後的人工檢核方式。

自編練習題｜測驗與解析

教材以哪個詞描述 Gems 的核心？
  • Persona
  • 印表機
  • 資料夾
  • 硬碟

答案：Persona。比較表以 Persona 說明角色與語氣設定。

教材以哪個詞描述 Skill 的核心？
  • Workflow
  • 字型
  • 投影機
  • 紙張

答案：Workflow。比較表以 Workflow 說明結構化步驟與檢核。

依教師決策指南，潤飾聯絡簿可優先考慮？
  • Gems
  • 網路交換器
  • 資料夾重新命名
  • 鍵盤驅動程式

答案：Gems。此工作偏向語氣、教學風格與彈性文字產出。

面對複雜格式，Gems 可能遇到什麼限制？
  • 跑版或遺忘規則
  • 必然停止供電
  • 無法輸入文字
  • 只能產出圖像

答案：跑版或遺忘規則。原稿提醒機率生成遇到嚴格限制時可能不一致。

5. 教材生產島

L4 生產層-任務

從文字走向教材檔案

原稿操作路徑

完成一套備課資源

@tw-spark-edu-lesson-pack-generator 請依據我提供的這份課本 PDF（或單元內容），為本課生成全套備課資源包，並將生成的 Google 文件、Google 簡報、結構圖圖片與 Kahoot 試算表，自動建立並存入 Google Drive『備課資料夾』中的專屬單元資料夾內。

6. 自動化中樞島

L5 系統層-Workspace

示意｜學習目標：能辨識觸發條件與後續動作，畫出教學行政工作流。

讓事件啟動工作流

Workspace 在原稿中是跨服務的教學行政整合中樞。透過事件觸發後續動作，串起收件、分析、紀錄與回饋。

原稿流程範例

Google Form 提交 → 呼叫 Gemini API 分析簡答 → 將評分內容寫入 Google Docs → 透過 Gmail 寄發回饋。這是教材介紹的外部工作流，本站僅供學習，不會代為串接或寄信。

原稿限制與評閱向度

原稿記載每帳號 25 個工作流、每工作流 20 個步驟。評閱範例以概念精確度、批判思辨力、實例佐證力、素養實踐力、邏輯表達力五向度，每項 20 分、共 100 分分析作答。

[角色任務]
  你現在是一位深耕教育評量與媒體識讀專業的「AI 閱卷評閱專家」。你的目標是針對學生的簡答題作答，提供客觀、精準且具教育啟發性的結構化評量。

  [背景資訊]
  學生剛完成以「AI與媒體識讀」為主題的簡答題測驗。我們需要透過五大核心向度來衡量學生的資訊素養與AI認知，以確保他們具備在數位時代辨識真偽的能力。

  [具體指令]
  請閱讀以下學生的作答內容，並嚴格依照下列五個向度（每個向度滿分20分，總計100分）進行計分與深度分析：
  1. 概念精確度（20分）：評估對AI術語與運作機制的理解正確性。
  2. 批判思辨力（20分）：評估分析AI生成內容潛在風險與偏見的能力。
  3. 實例佐證力（20分）：評估使用具體案例支持自身觀點的能力。
  4. 素養實踐力（20分）：評估提出的事實查核步驟或防範策略是否具體可行。
  5. 邏輯表達力（20分）：評估文意通順度與論述結構的嚴謹性。

  針對學生的作答，請產出以下回覆：
  - 【總分評定】：給出總分（/100）。
  - 【雷達圖分析】：列出五個向度的個別得分。
  - 【優勢與亮點】：具體點出作答中表現最優異的1至2個面向。
  - 【成長鷹架】：針對失分項目，提出具體且可操作的改善建議。

  [約束條件]

7. 任務 vs Studio

進階架構比較

示意｜學習目標：能區分單次主動產出與事件自動化，安排適用的教學階段。

主動產出與事件觸發

Spark（任務）由老師在備課時主動喚醒，處理當次素材；Workspace Studio 則依設定的事件啟動後續流程。

比較成果與階段

Spark 重點是多模態教材打包與歸檔，適合課前備課；Workspace Studio 重點是資料流轉與派發，適合課中、課後作業處理。

把兩種引擎接起來

先以任務將文本轉成教案、簡報與題庫，再規劃學生提交後的分析、紀錄與回饋流程。依需求選擇工具，把時間留給教學中的溫度與關懷。
